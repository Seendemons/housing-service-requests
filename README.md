# housing-service-requests

Курсовой проект «Система обработки заявок жителей многоквартирного дома
с использованием нейросети». Приложение рассчитано на один дом.

## Что уже работает

- Вход под демонстрационными аккаунтами жителя и диспетчера.
- Создание и редактирование своих черновиков, ручная отправка диспетчеру.
- Просмотр своих заявок и истории изменений жителем.
- Список отправленных заявок и фильтр по статусу для диспетчера.
- Назначение исполнителя из справочника и перевод заявки в работу.

Текущий путь: **черновик → новая → в работе**.
Закрытие заявок, фото/видео и проверка текста нейросетью ещё не реализованы.
У исполнителей нет отдельных аккаунтов.

## Стек и требования

FastAPI, Jinja2, PostgreSQL 17, синхронный SQLAlchemy 2 + psycopg, Alembic.
Для локального запуска нужны Python 3.13, uv и Docker с работающим
Docker Engine и Docker Compose v2.

## Локальный запуск

Все команды выполняются из корня проекта.

### 1. Установите зависимости и подготовьте настройки

```bash
uv sync
cp -n .env.example .env
```

Команда копирования не перезаписывает существующий `.env`.
Если он уже есть, добавьте недостающие настройки из `.env.example` вручную.
В `.env` задайте свои непустые пароли:

- `POSTGRES_PASSWORD` — замените пример пароля БД;
- `DEMO_RESIDENT_PASSWORD` — пароль жителя;
- `DEMO_DISPATCHER_PASSWORD` — пароль диспетчера.

Для локального HTTP оставьте `SESSION_COOKIE_SECURE=false`.
`.env` загружается автоматически и игнорируется Git.

### 2. Запустите PostgreSQL

```bash
docker compose config --quiet
docker compose up -d db
docker compose ps
```

Дождитесь состояния `healthy` у сервиса `db`.
По умолчанию приложение подключается к `127.0.0.1:5432`.
Если порт занят, измените `POSTGRES_PORT` в `.env` до запуска БД.

### 3. Примените миграции и создайте демо-данные

```bash
uv run alembic upgrade head
uv run python -m app.seed_demo
uv run python -m app.seed_executors
```

Логины — `resident` и `dispatcher`, пароли — заданные вами в `.env`.
Повторный запуск команд заполнения сохраняет существующих пользователей
и исполнителей; пароли существующих аккаунтов не меняются.

### 4. Запустите приложение

```bash
uv run uvicorn app.main:app --reload
```

Откройте [приложение](http://127.0.0.1:8000/) или
[страницу входа](http://127.0.0.1:8000/login).
[Документация API](http://127.0.0.1:8000/docs) доступна при работающем сервере.

Для остановки сервера нажмите `Ctrl+C`. Для остановки БД:

```bash
docker compose down
```

Данные сохраняются в томе `postgres_data`. Изменение пароля в `.env`
не меняет пароль уже созданной БД; подробнее — в [настройке БД](docs/development.md#postgresql).

## Быстрая демонстрация

1. Войдите как `resident`, создайте черновик с местоположением и описанием.
2. Откройте его, проверьте редактирование и нажмите «Отправить диспетчеру».
3. Выйдите и войдите как `dispatcher`, откройте новую заявку.
4. Выберите исполнителя и нажмите «Назначить и начать работу».
5. Снова войдите как `resident`: в карточке видны статус «В работе», исполнитель и история.

Подробный [сценарий демонстрации](docs/demo.md) содержит ожидаемые результаты
и ограничения текущей версии.

## Проверки

```bash
uv sync --dev
uv run ruff check .
uv run ruff format --check .
uv run pytest
```

Автотесты используют SQLite и не требуют запущенной PostgreSQL.
Они не заменяют проверку с настоящей PostgreSQL и в браузере.
