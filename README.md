# housing-service-requests

Репозиторий проекта для работы с заявками в жилищную службу.

Проект находится на начальном этапе разработки. Настроено окружение Python,
добавлено минимальное приложение FastAPI с главной HTML-страницей.

## Окружение разработки

Используются Python 3.13 и менеджер зависимостей uv.

Из корня проекта выполните:

```bash
uv sync
uv run python --version
```

`uv sync` создаёт окружение `.venv` и устанавливает зависимости по `uv.lock`.
`uv run` запускает команды в окружении проекта без ручной активации.
Ожидаемая версия Python — 3.13.x.

В PyCharm выберите существующий интерпретатор `.venv/bin/python`
в настройках Python Interpreter.

## Запуск приложения

Из корня проекта выполните:

```bash
uv run uvicorn app.main:app --reload
```

Откройте <http://127.0.0.1:8000/> — появится главная страница.
Документация API доступна по адресу <http://127.0.0.1:8000/docs>.
Пока в приложении есть только маршрут главной страницы.

`app.main:app` указывает на объект `app` в файле `app/main.py`.
Uvicorn запускает веб-сервер, а `--reload` перезапускает его после изменений
Python-кода. Этот режим предназначен для локальной разработки.
Чтобы остановить сервер, нажмите `Ctrl+C` в терминале.

## Настройки приложения

Без `.env` приложение работает с настройками по умолчанию. При необходимости
создайте локальный файл из безопасного шаблона (из корня проекта):

```bash
cp -n .env.example .env
```

Команда не перезаписывает существующий `.env`. Отредактируйте его при необходимости:

- `APP_NAME` — непустое название приложения; по умолчанию «Заявки в жилищную службу».
- `APP_DEBUG` — режим отладки FastAPI: `true` или `false`, по умолчанию `false`.

`.env` загружается автоматически из корня проекта независимо от каталога запуска;
переменные окружения имеют приоритет. Локальная `.env` игнорируется Git,
а `.env.example` хранится в репозитории только как шаблон и сам не загружается.
Команда запуска остаётся прежней.

## PostgreSQL через Docker Compose

Подготовлена конфигурация PostgreSQL 17; приложение пока не подключено к БД.
Для будущего запуска нужны установленный Docker с работающим Docker Engine
и Docker Compose v2 (`docker compose`). Установка и запуск БД ещё не проверены.

Из корня проекта создайте `.env` без перезаписи существующего файла:

```bash
cp -n .env.example .env
```

Если `.env` уже существует, вручную добавьте в него недостающие `POSTGRES_DB`,
`POSTGRES_USER`, `POSTGRES_PASSWORD` и `POSTGRES_PORT` из `.env.example`,
сохранив свои настройки приложения. Замените вымышленный пример пароля своим
непустым паролем перед запуском. Переменные окружения имеют приоритет над `.env`.

После установки Docker проверьте конфигурацию без вывода значений и секретов:

```bash
docker compose config --quiet
```

Для будущего запуска и проверки состояния:

```bash
docker compose up -d db
docker compose ps
```

После инициализации ожидается состояние `healthy` у сервиса `db`.
При подключении приложения с этого компьютера используйте хост `127.0.0.1`,
порт из `POSTGRES_PORT` (по умолчанию `5432`), имя БД из `POSTGRES_DB`,
пользователя из `POSTGRES_USER` и пароль из `POSTGRES_PASSWORD`.
В шаблоне имя БД — `housing_requests`, пользователь — `housing_user`.
Порт БД доступен только на локальном интерфейсе компьютера.

Для остановки:

```bash
docker compose down
```

Именованный том `postgres_data` сохраняет данные после `docker compose down`.
Переменные `POSTGRES_DB`, `POSTGRES_USER` и `POSTGRES_PASSWORD` применяются при
первой инициализации пустого тома. Изменение `.env` не меняет автоматически
пароль, пользователя или имя уже созданной БД.

Справка: [официальный образ PostgreSQL](https://hub.docker.com/_/postgres),
[проверка конфигурации Compose](https://docs.docker.com/reference/cli/docker/compose/config/)
и [остановка Compose](https://docs.docker.com/reference/cli/docker/compose/down/).

## Структура

```text
app/
  __init__.py
  config.py             # Настройки приложения и чтение .env
  main.py               # Приложение FastAPI и маршрут главной страницы
  templates/
    index.html          # HTML-шаблон главной страницы
pyproject.toml          # Настройки проекта и зависимости
uv.lock                 # Зафиксированные версии зависимостей
```

FastAPI обрабатывает запрос браузера, Jinja2 формирует HTML по шаблону,
а Uvicorn принимает HTTP-запросы и передаёт их приложению.

Вход и работа с заявками пока не реализованы.

## Проверки

Из корня проекта установите зависимости разработки и выполните проверки:

```bash
uv sync --dev
uv run ruff check .
uv run ruff format --check .
uv run pytest
```

Ruff проверяет код и форматирование, а pytest проверяет настройки и главную HTML-страницу.
