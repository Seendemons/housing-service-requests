# Разработка

[README](../README.md) содержит последовательный локальный запуск.
Здесь собраны дополнительные настройки и пояснения к устройству проекта.

## Окружение

`uv sync` создаёт `.venv` и устанавливает зависимости по `uv.lock`.
`uv run` запускает команды в этом окружении без ручной активации.
Проверить версию Python можно командой `uv run python --version`;
проект использует Python 3.13.x.
В PyCharm выберите интерпретатор `.venv/bin/python`.

В команде `uv run uvicorn app.main:app --reload` запись `app.main:app`
указывает на объект `app` в файле `app/main.py`. Uvicorn принимает HTTP-запросы,
FastAPI обрабатывает их, Jinja2 формирует HTML по шаблонам.
`--reload` перезапускает сервер после изменений Python-кода и предназначен
для локальной разработки.

## Настройки

Приложение читает `.env` из корня проекта независимо от каталога запуска.
Переменные окружения имеют приоритет над `.env`.
`.env.example` служит шаблоном и сам не загружается.

| Переменная | Назначение / значение по умолчанию |
| --- | --- |
| `APP_NAME` | Непустое название, «Заявки в жилищную службу» |
| `APP_DEBUG` | Отладка FastAPI, `false` |
| `POSTGRES_HOST` | Хост подключения приложения, `127.0.0.1` |
| `POSTGRES_PORT` | Порт на компьютере, `5432` |
| `POSTGRES_DB` | Имя БД, `housing_requests` |
| `POSTGRES_USER` | Пользователь БД, `housing_user` |
| `POSTGRES_PASSWORD` | Свой непустой пароль БД |
| `SESSION_COOKIE_SECURE` | `false` для локального HTTP, `true` для HTTPS |
| `DEMO_RESIDENT_PASSWORD` | Свой непустой пароль для создания жителя |
| `DEMO_DISPATCHER_PASSWORD` | Свой непустой пароль для создания диспетчера |

После изменения настроек перезапустите приложение.
Главная страница и импорт приложения работают без БД;
для входа и работы с заявками нужна PostgreSQL с применёнными миграциями.

## PostgreSQL

Compose запускает PostgreSQL 17 и публикует порт только на `127.0.0.1`.
`POSTGRES_HOST` задаёт адрес подключения приложения, Compose его не использует.
`docker compose config --quiet` проверяет конфигурацию без вывода её значений.

Том `postgres_data` сохраняется после `docker compose down`.
`POSTGRES_DB`, `POSTGRES_USER` и `POSTGRES_PASSWORD` применяются при первой
инициализации пустого тома. Изменение `.env` не меняет имя, пользователя
или пароль уже созданной БД. При повторном запуске используйте настройки,
с которыми она была создана.

Дополнительная проверка соединения из корня проекта:

```bash
uv run python - <<'PYTHON'
from sqlalchemy import text
from app.database import get_engine

with get_engine().connect() as connection:
    print(connection.scalar(text("SELECT 1")))
PYTHON
```

Ожидаемый результат — `1`.

## Подключение и модели

`app.database.get_engine()` создаёт и сохраняет engine при первом обращении;
соединение устанавливается при запросе. `get_db()` выдаёт синхронную
SQLAlchemy Session, откатывает транзакцию при ошибке и закрывает сессию.
Успешные изменения обработчик подтверждает явным `db.commit()`.

Модели описывают пользователей (`users`), серверные сессии (`auth_sessions`),
исполнителей (`executors`), заявки (`service_requests`) и историю (`request_history`).
Роли пользователей — `resident` и `dispatcher`; исполнители — отдельный справочник.
Статусы в схеме — `draft`, `new`, `in_progress`, `closed`.
Создание статуса в схеме не означает наличие всех переходов в интерфейсе.

Заявка связана с жителем и, после назначения, с исполнителем.
История содержит автора и переход статуса; изменение статуса и запись истории
сохраняются одной транзакцией. Внешние ключи заявок и истории защищают
связанные записи от удаления.
Пароли хранятся в виде хешей. Серверная сессия действует до восьми часов,
браузер хранит её идентификатор в cookie; изменяющие формы защищены CSRF.

Даты создаются в UTC; для прямых вставок база также задаёт текущее время.
`updated_at` обновляется при изменениях через SQLAlchemy, триггера в БД нет.
SQLite не сохраняет сведения о часовом поясе при чтении дат.

Миграции применяются командой `uv run alembic upgrade head`.
Текущую ревизию показывает `uv run alembic current`.

## Демо-данные

`uv run python -m app.seed_demo` создаёт `resident` и `dispatcher`.
Оба пароля должны быть заданы даже при повторном запуске.
Существующие пароли и роли сохраняются; при конфликте роли операция откатывается.

`uv run python -m app.seed_executors` добавляет демо-сантехника и демо-электрика.
Существующие записи с такими именами и их специализация сохраняются.
Аккаунты исполнителей не создаются. Заполнение выполняется явно,
приложение не запускает эти команды автоматически.

## Структура

```text
app/
  config.py             # Настройки и чтение .env
  database.py           # Engine и сессии SQLAlchemy
  models.py             # Модели данных
  auth.py               # Пароли, сессии, роли и CSRF
  seed_demo.py          # Создание демо-пользователей
  seed_executors.py     # Заполнение справочника исполнителей
  main.py               # Маршруты приложения
  templates/            # HTML-шаблоны
  static/               # Стили
migrations/             # Миграции и окружение Alembic
alembic.ini             # Настройки Alembic без пароля
compose.yaml            # PostgreSQL и том данных
pyproject.toml          # Зависимости и настройки инструментов
uv.lock                 # Зафиксированные версии зависимостей
tests/                  # Автотесты
docs/                   # Дополнительная документация
```

## Проверки и их границы

Команды Ruff и pytest приведены в [README](../README.md#проверки).
Автотесты проверяют настройки, авторизацию, сессии, права, CSRF,
создание и редактирование черновиков, отправку, списки и историю заявок,
назначение исполнителя, повторные действия и откат при ошибках.
Также проверяются команды заполнения, модели и миграции на SQLite,
диапазон номеров заявок и генерация SQL для PostgreSQL.

Штатный `pytest` не требует PostgreSQL и не запускает браузер.
Он не подтверждает работу миграций, ограничений и конкурентных операций
на настоящей PostgreSQL. Для ручной проверки используйте
[сценарий демонстрации](demo.md) на отдельной тестовой БД.
