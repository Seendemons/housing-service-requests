# Сценарий демонстрации

Перед началом выполните [локальный запуск](../README.md#локальный-запуск),
включая миграции и обе команды заполнения демо-данных.
Сценарий создаёт настоящие записи: для проверки используйте отдельную тестовую БД.
Пароли аккаунтов — заданные вами при их создании.

## 1. Создание и редактирование черновика

1. Откройте [вход](http://127.0.0.1:8000/login) и войдите как `resident`.
2. В кабинете `/resident` нажмите «Создать черновик».
3. Укажите местоположение, например «Подъезд 1, этаж 2», и описание:
   «Протекает труба у лестницы, на полу скапливается вода».
4. Нажмите «Сохранить черновик» — откроется карточка со статусом «Черновик».
5. Нажмите «Редактировать», дополните описание и сохраните изменения.

Проверьте: текст обновился, дата создания сохранена; «Отмена» возвращает
в карточку без сохранения. Оба текстовых поля обязательны, пробелы по краям
удаляются. Местоположение ограничено 255 символами, описание — 10 000.
При ошибке форма показывает пояснение и сохраняет введённые значения.

Свои заявки доступны из списка в кабинете, новые записи показаны первыми.
После выхода и повторного входа черновик остаётся доступным.

## 2. Отправка диспетчеру

В карточке нажмите «Отправить диспетчеру».

Ожидаемый результат:

- статус изменился на «Новая»;
- в истории появился переход «Черновик → Новая» с логином автора и временем UTC;
- редактирование стало недоступно, карточка и история остались доступны жителю.

Отправка пока выполняется вручную, без проверки ИИ.
Повторный запрос отправки не создаёт дубль истории.

## 3. Назначение исполнителя

1. Нажмите «Выйти» и войдите как `dispatcher`.
2. В `/dispatcher` найдите отправленную заявку. Черновики в список не входят.
3. Выберите статус «Новая» и нажмите «Показать»; «Сбросить фильтр» возвращает все заявки.
4. Откройте карточку: видны логин жителя, местоположение, описание, статус и история.
5. Выберите исполнителя и нажмите «Назначить и начать работу».

Ожидаемый результат: статус «В работе», выбранный исполнитель и запись истории
с логином диспетчера и временем UTC. Если справочник пуст, форма назначения
недоступна: заполните его командой из инструкции запуска.
Повторное назначение для заявки в работе запрещено.

## 4. Просмотр результата жителем

Выйдите и снова войдите как `resident`. Откройте ту же заявку:
статус «В работе», исполнитель и история должны быть видны после повторного входа.
Житель видит только свои заявки; страницы диспетчера ему недоступны.
Диспетчер видит отправленные заявки всех жителей; черновики недоступны
даже по прямому адресу.

## Граница текущей демонстрации

Путь заканчивается назначением исполнителя и статусом «В работе».
Закрытие с итоговым комментарием, фото/видео и проверка текста нейросетью
ещё не реализованы. В схеме и фильтре есть статус «Закрыта»,
но перевести заявку в него через интерфейс пока нельзя.
У исполнителей есть только записи справочника, отдельных кабинетов нет.
